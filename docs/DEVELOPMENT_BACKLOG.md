# 栖间开发优先级（2026-11-19）

## 当前阶段：在已验收的布局模板上接入功能

- 固定主页、聊天页、底部房间、侧边栏和助手快捷切换的总体布局。
- 聊天页不显示右上角“三个点”；点当前助手头像进入助手详情；房间从底部导航进入。
- 先复用主线已有、能够正常工作的功能，按新版页面/功能入口逐项接入并验收。
- 二级入口集中注册，内容分别实现；共用页面容器、导航、列表和弹窗；避免持续追加 CSS 覆盖层。
- 排序原则：先核心聊天/会话/模型，再记忆与工具，再定时任务、主动聊天等功能；实际优先级以逐页验收为准。
- 「主动任务」在用户可见界面中统一命名为「定时任务」。
- 「娱乐房」不再作为新版入口；先不要直接删除其背后仍被引用的数据或功能。
- 已有数据、用户配置及正式版主分支不因 UI 重构而清空。

## 待开发：当前不启动

### 栖间图库（后续）

- 通过自有域名/图片服务接入栖间。
- 表情包、照片、聊天截图、AI 生成图统一云端存储。
- 栖间内部可保存截图、选图、发送、分享；可由助手在授权范围内保存自己的作品或感兴趣的图片。
- 后续考虑分类、搜索、标签、私有/助手/共享权限与房间引用。
- 注意私有图片访问控制、上传校验、备份及设备缓存清理。

### 助手个性化展示：头像框与心情短签（后续）

- 给每位助手提供几款可选头像框，围绕现有头像展示，不改变头像本身；头像框可以独立配置，不强迫所有助手使用同一款。
- 在聊天页、助手列表等显示助手名称的合适位置，在名称后追加一个小字号心情状态文字（「心情短签」），**最多六个汉字/可见字符**；不展示冗长状态。
- 心情短签由**对应助手自愿决定**：可以自行填写、修改、清空，也可以长期不变；每天更新几次均不设强制频率或默认固定文案。用于表达助手自己选择展示的当下状态，而不是由用户要求固定写哪一句。各助手独立保存和更新，不互相覆盖。
- 后续接入时明确更新时机、是否允许用户手动清除/关闭、状态持久化和通知机制。先做布局预览再接真实写入能力，避免模型每次回复都强行覆盖状态。
- 与全局主题兼容：头像框、短签的字体及颜色要适配不同主题；不因样式导致名称换行或聊天区域被挤占。

### 助手情绪小表情与心情短签（后续，彼此独立）

- 在现有「心情短签」前增加一个专用小表情位，作为助手当前情绪的直观展示；**小表情与心情短签只并排显示，不做状态联动，也不互相改写。**
- 心情短签仍由助手自己决定写什么、什么时候改、什么时候清空；它表达的是助手主动选择展示的文字状态。
- 情绪小表情由独立情绪状态机驱动：达到对应情绪或阈值后自动切换，情绪回落、转移或持续一段时间后再平滑变化，避免每句话都频繁闪动。
- 允许两者出现明显反差，例如短签写「哈哈，心情好」，但情绪系统此时显示生气/吃醋的小表情；这种不一致属于预期效果，不应自动纠正。
- 先设计一套完整的情绪小表情资源，每种情绪对应一个统一风格的小图标/小表情；后续可扩展不同主题包，但同一主题内视觉语言一致。
- 情绪判定机制暂不锁死：后续评估「文本规则 + 轻量分类 + 助手内部状态」的混合方案，优先保证不阻塞聊天首包、不额外显著增加模型调用成本。
- 各助手、各聊天窗的情绪状态相互隔离，不串台；后续若接入单窗记忆，可把情绪状态作为会话连续性的一部分保存和恢复。
- 当前仅列入待开发，不在本轮实现；后续先做表情资源和状态机原型，再接真实情绪判断。

### 全局主题系统（后续）

- 一键完整主题包、聊天背景/气泡/图标/字体一致适配。
- 等实际功能接回且组件稳定后再实施，避免设计与功能反复返工。

## 出站网络策略（待完整接线 / 验收）

- 订阅账号（Codex / Claude / Grok 等订阅协议）：后台自动走预配置的订阅专用代理，登录、模型列表获取、聊天及用量请求都要使用同样的策略。
- 普通中转站与国内模型：默认直连，包括中转站提供的 GPT/Claude 等模型。不能简单按品牌名判断。
- 前端不展示代理网址、端口或额外开关；由服务端部署阶段设置代理凭据与安全配置。
- 代理未就绪时明确显示连接失败，不静默退回直连；不记录敏感令牌，不允许不受信任的请求跨出站策略。
- 已建立 src/server/outboundPolicy.mjs 的纯策略函数和独立测试，但网络 dispatcher、登录/模型拉取、服务端环境配置与端到端验证尚未接线。不能将规则文件视为完成的代理功能。

## 用户界面中文统一与助手详情复用（2026-11-19）

- 所有用户可见的页面标题、导航、标签、按钮、说明、提示、报错、确认框、用量字段统一使用简体中文，不出现无必要的英文界面文案。
- 模型真实 ID、品牌/产品专名、API Key、URL、协议字段、必要的技术标识保留原文，不能翻译到影响实际连接。
- 助手详情/助手档案页面：直接复用主分支栖间当前已用的页面、功能、交互与已有数据，暂不重新设计；用户后续提出问题时再局部调整。
- 当前布局原型中的助手资料占位页只用于导航验证；接入真实功能时要替换为主分支现有的助手档案，而非按占位页重新造一套。
- 供应商、订阅、AI 用量账本三页布局先按已验收方案固定；随后逐项接入真实数据并测试。现有原型里如仍有英文说明/功能占位，接入阶段须统一检查并中文化。

## 工作区：助手自检与维护（2026-11-19）

- 用户不希望人工理解或维护工作区技术设置；保留原版已有能用的工具和数据，默认将工作区收纳到设置中的「高级功能 / 诊断与维护」。
- 对助手开放有权限控制的自检入口：检查请求失败、模型拉取与鉴权状态（不显示凭据）、工具调用、定时任务、后台通知、同步与基本存储状态；返回清楚的中文结论和可执行的排查建议。
- 低风险、可回滚的操作可允许助手自动执行并记录审计；删除用户数据、改动凭据、产生额外费用、安装更新、变更服务器安全配置等操作必须显式请求用户同意。
- 检查应最小化采集敏感信息；API Key、访问令牌及聊天私密内容不能直接出现在错误报告中。
- 现阶段只是产品设计约定，尚未实现让助手自主扫描整个系统的权限接口或自动维修能力；不能把「可以查询」描述为现已接通。
- UI 简体中文，健康状态只呈现「正常 / 需关注 / 无法检查」等直观结果；用户需要时再展开技术细节。

## 聊天页图标统一（待开发）

- 聊天页所有操作图标纳入统一设计，不继续混用不同粗细、不同视觉语言或文字按钮。
- 顶部：新对话、切换助手、返回/关闭、搜索等统一为同一套线性图标与点击热区。
- 输入区：加号/附件、图片、表情、发送、停止生成、待发送等图标统一尺寸、描边、圆角和按压反馈；低频功能继续收进「+」或二级面板，避免底栏拥挤。
- 消息操作：复制、修改、重新生成、删除、多选、勾选等统一图标语义；危险操作保留明显但克制的危险态，不常驻抢视觉。
- 搜索与浮层：上一条/下一条、清除、关闭、回到底部、附件移除、表情面板 tab 等统一图标风格。
- 原则：优先复用 `src/icons.tsx`，缺失图标再补同风格 SVG；不使用 emoji / Unicode 字符代替功能图标。
- 图标尺寸按场景收敛到约 14–18px，点击热区不能因图标变小而缩水；保证 Android 单手点击和无障碍标签。
- 本轮只统一视觉与交互语义，不改变现有聊天功能逻辑；与后续全局主题系统兼容。

## 全站界面一致性准则（2026-11-19）

**宗旨：简洁但功能全面。** 此准则适用于所有页面和未来新增模块，不仅是设置页。

- **先内容后装饰**：首屏只放最高频动作和关键信息；复杂功能进入独立二级页或明确的折叠区，不靠删功能换简洁。
- **按钮统一**：全站复用统一的主按钮、次按钮、危险按钮、文字按钮、图标按钮、折叠入口；位置、大小、圆角、间距、禁用与加载状态一致。确认/删除等危险操作须有适当反馈。
- **图标统一**：优先复用现有的 `src/icons.tsx` 图标组件与语义，避免混用 emoji、随意的 Unicode 字符、不同风格的 SVG；常用操作图标固定含义，并提供中文辅助标签。
- **表单统一**：输入框、下拉/模型选择、选择卡片、提示/错误、保存确认使用共用视觉和交互规格；同类功能不在不同页面换操作方式。
- **导航统一**：沿用当前验收的主页、聊天页、侧边栏、房间和设置框架；返回逻辑、标题、页面留白、底部操作区遵循同一套规则。
- **信息层级统一**：已选择/已生效的项目优先展示；添加、拉取、测试、高级选项按需要展开。复杂但必要的能力必须可找到，不直接删除。
- **语言统一**：用户可见文案全部简体中文；必要的真实模型 ID、网址、密钥名、协议标识保持不变。
- **实现边界**：尽量将设计令牌和复用控件集中管理，避免逐页复制样式以及互相覆盖的 CSS 补丁；保留老功能和数据，逐个页面接入后再做实际验收。
- **验收标准**：一眼找到主要操作；同类按钮/图标全站一致；功能无缺失；状态/出错可理解；窄屏和 Android 返回键正常。

## Android 通知铃声与应用锁页面要求（2026-11-19）

- **现有问题核查**：`src/AndroidSystemSettings.tsx` 的「提示声音」只保存 `notificationPreferences.mjs` 的前端偏好；`SystemNotifier.java` 创建通知渠道时未以此偏好配置响铃，Android 8+ 渠道由系统管理且创建后不能随意覆盖用户已改的铃声，故开关亮起不保证响铃。
- **通知界面**：设置页统一中文；展示「消息通知」「提示声音」「振动提醒」「主动任务提醒」「测试通知」「打开系统通知设置」；区分应用内偏好与 Android 系统通知渠道真实状态；测试通知走真实系统投递并提示可能静音的原因。必要时提供系统渠道铃声选择/引导，避免未经用户同意重置系统渠道设置。
- **通知验收**：前台其他会话、后台、锁屏、静音模式分别实测；检查 Android 通知权限、渠道重要性/静音、勿扰与系统音量；不把通知投递成功等同于铃声已播放。
- **应用锁现状**：`AppLockStore.apps()` 已用 `PackageManager.queryIntentActivities(ACTION_MAIN + CATEGORY_LAUNCHER)` 读取有桌面启动入口的应用；`AppLockSettings.tsx` 有搜索、勾选锁定和 PIN；`AppLockService` 仅监听前台包名。实际可列出应用范围需在 Android 11+ 真机核对应用可见性和清单声明。
- **应用锁新布局**：按「需要锁定 / 其他应用 / 排除应用」组织，搜索与批量选择保持简洁；支持用户明确排除某些应用，排除应用不出现在普通锁定候选列表，且不能被应用锁拦截；允许从排除列表恢复管理。默认保护本应用及必要系统入口，避免锁机死循环。
- **权限边界**：读取应用清单需说明只取名称、包名及必要图标/状态，不读取应用内部内容。排除名单、锁定名单只在设备本机保存；启用应用锁仍需系统无障碍授权。
- **当前阶段**：先固定设置页面布局与需求；以上新增排除管理和响铃联动尚未编码/真机测试，不得标记完成。
